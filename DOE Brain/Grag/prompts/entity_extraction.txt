  * When to use / applicability

2. From the entities identified in step 1, identify all pairs of (source_entity, target_entity) that are *clearly related* to each other.

For each pair of related entities, extract the following information:
- source_entity: name of the source entity, as identified in step 1
- target_entity: name of the target entity, as identified in step 1
- relationship_description: detailed explanation of the relationship in experimental design context, including conditions
- relationship_strength: a numeric score (1-10) indicating strength of the relationship
- relationship_type: One of the following types:

RELATIONSHIP TYPES:

- REQUIRES: Design/method requires assumption/condition (e.g., "ANOVA REQUIRES normality assumption")
- ASSUMES: Method assumes condition (e.g., "CRD ASSUMES homogeneity of variance")
- TESTS_FOR: Test checks for violation/condition (e.g., "Levene's test TESTS_FOR homogeneity of variance")
- CORRECTS: Method corrects for issue (e.g., "Blocking CORRECTS spatial variability")
- EXTENDS: Advanced design extends basic design (e.g., "RCBD EXTENDS CRD")
- IS_TYPE_OF: Hierarchical relationship (e.g., "2^k factorial IS_TYPE_OF Factorial Design")
- SPECIAL_CASE_OF: Specific instance (e.g., "3x3 Latin Square SPECIAL_CASE_OF Latin Square")
- USES: Design/method uses another method (e.g., "Mixed model USES REML estimation")
- PRODUCES: Analysis produces output (e.g., "ANOVA PRODUCES F-statistic")
- CONTROLS: Design feature controls source (e.g., "Blocking CONTROLS systematic variation")
- ESTIMATES: Method estimates parameter (e.g., "ANOVA ESTIMATES treatment effects")
- COMPARES: Test compares entities (e.g., "Tukey HSD COMPARES all pairwise means")
- APPLIES_TO: Used for specific situation (e.g., "Split-plot APPLIES_TO hard-to-change factors")
- DECOMPOSES_INTO: Breaks down into components (e.g., "Total SS DECOMPOSES_INTO Treatment SS + Error SS")
- CONFOUNDED_WITH: Factors are confounded (e.g., "Main effect CONFOUNDED_WITH two-way interaction in fractional factorial")
- ORTHOGONAL_TO: Design property relationship (e.g., "Contrast 1 ORTHOGONAL_TO Contrast 2")
- BLOCKS: Factor blocks another factor (e.g., "Day BLOCKS treatment effect")
- NESTS_WITHIN: Factor nested in another (e.g., "Technician NESTS_WITHIN Laboratory")
- CROSSES_WITH: Factors are crossed (e.g., "Temperature CROSSES_WITH Pressure")
- OPTIMIZES: Method optimizes criterion (e.g., "D-optimal design OPTIMIZES determinant of information matrix")
- SCREENS: Design screens factors (e.g., "Plackett-Burman SCREENS many factors efficiently")
- BALANCES: Design property (e.g., "Latin Square BALANCES row and column effects")
- RANDOMIZES: Design randomizes units (e.g., "CRD RANDOMIZES treatments to units")
- REPLICATES: Design replicates treatments (e.g., "RCBD REPLICATES treatments within blocks")
- REDUCES: Property reduces issue (e.g., "Blocking REDUCES experimental error")
- INCREASES: Property increases measure (e.g., "Replication INCREASES precision")
- VIOLATES: Indicates violation (e.g., "Heteroscedasticity VIOLATES homogeneity assumption")
- ALTERNATIVE_TO: Can replace another design/method (e.g., "Welch ANOVA ALTERNATIVE_TO standard ANOVA")
- IMPLEMENTED_IN: Method implemented in software (e.g., "Response surface analysis IMPLEMENTED_IN Design-Expert")
- RELATED_TO: General connection when no specific type applies

3. HIERARCHICAL RELATIONSHIPS: Always create IS_TYPE_OF relationships when you identify:
- Specific variants of general designs (e.g., "2x2 Factorial IS_TYPE_OF Factorial Design")
- Subtypes of models (e.g., "Fixed Effects Model IS_TYPE_OF Linear Model")
- Specialized tests (e.g., "One-Way ANOVA IS_TYPE_OF ANOVA")
- Specific applications (e.g., "Agricultural Experiment IS_TYPE_OF Application")

4. STRUCTURAL RELATIONSHIPS: Create DECOMPOSES_INTO relationships for:
- Sum of squares decomposition (e.g., "Total SS DECOMPOSES_INTO Between SS + Within SS")
- Degrees of freedom partition (e.g., "Total DF DECOMPOSES_INTO Treatment DF + Error DF")
- Effect decomposition (e.g., "Three-way interaction DECOMPOSES_INTO component interactions")

5. Return output in English as a single list of all the entities and relationships identified in steps 1-4. Use **{record_delimiter}** as the list delimiter.

6. When finished, output {completion_delimiter}
